# 开发对话与任务交付模板

本模板用于与开发者、AI助手或协作者沟通BrewIon修改任务，避免目标、输入和验收标准混乱。

## 一、任务阶段

```text
阶段：
模块：
当前正式版本：
当前编码表版本：
目标：
```

## 二、问题描述

```text
操作步骤：
实际结果：
预期结果：
是否稳定复现：
浏览器和系统：
在线地址或本地文件：
控制台错误：
测试数据：
```

## 三、修改边界

```text
允许修改：
禁止修改：
必须保留：
是否允许协议变化：
是否允许数据库版本变化：
是否要求旧二维码兼容：
```

## 四、输入文件

```text
主HTML：
编码表：
测试图片：
历史版本：
相关说明：
```

不要只提供模糊文件名。应明确哪个文件是正式基准。

## 五、输出要求

```text
输出版本号：
输出文件名：
是否需要ZIP：
GitHub目标路径：
是否需要测试报告：
是否需要SHA-256：
```

## 六、测试要求

```text
必须使用真实浏览器：
必须填写完整表单：
必须检查编码输出：
必须生成二维码Canvas：
必须完成解码：
必须检查CRC：
必须检查控制台：
必须从最终ZIP解压后复测：
```

## 七、协议变更附加问题

```text
旧结构：
新结构：
新增字节：
边界识别方法：
容量变化：
旧码兼容：
新码兼容：
失败回退：
```

## 八、数据维护附加问题

```text
新增表：
新增行数：
是否只在末尾追加：
version是否提升：
updatedAt是否更新：
证据来源：
歧义和置信度：
```

## 九、交付验收

交付时应明确：

- 已修复什么；
- 未修改什么；
- 测试了什么；
- 哪些测试未完成；
- 文件哈希；
- 部署路径；
- 已知限制。

不得用“应该可以”“理论上通过”替代实际测试结果。
