# 富贵盒子 Lucky Bean

**当前内部测试版本：v0.9.9**  
**稳定网址：<https://zjcrop.github.io/BrewIon/luckybean/>**

富贵盒子是本地优先的咖啡豆档案、冲煮方案和感官品鉴工具。1.0 之前均属于内部测试版本，允许直接在 `main` 修改和部署；仓库根目录 `index.html` 是唯一源码入口，正式网页由 `BrewIon/main/luckybean/` 同步发布，不维护独立 Beta 页面或长期发布支线。

## v0.9.9

- 修复点击分组后因菜单观察器自触发造成的页面卡死；
- 修复连续使用“选择”时第二次不展开分组的问题；
- 四象限菜单中央拖拽热区扩大但完全透明；
- “专业内容”改为“深入解读”，修正黑白主题正文颜色；
- 新增并验算 Hoffmann、April、Matt Winton、Lance、Switch、Mugen、Onyx 等公开冲煮结构；
- 轨迹优化以穿越正向风味窗口、避开负面风险窗口为核心目标，同时搜索温度、流量、时间、研磨、粉水比和分段水量；
- 一刀流改为单一连续阶段，33666固定为五段；
- 第二雷达图增加干净度、一致性和平衡度，新增瑕疵标签与扣分。

## v0.9.8

### 豆卡、分组与归档

- 选中的豆卡在黑色模式显示深灰底、白色模式显示浅灰底，选择状态更明确；
- 默认按烘焙度分组；新增按赏味状态分组，顺序为衰减在前、最新鲜在后；
- 新增按剩余克重分组，以 50 g 为一个区间；
- 已归档豆卡增加“复购 / 分享 / 删除”操作；复购时必须重新填写烘焙日期与克重；删除豆卡时同步清理关联记录。

### 冲煮方案与 v17 轨迹

- 冲煮阶段数量统一包含闷蒸：两段式为“闷蒸 + 1 次主体注水”，三段式为“闷蒸 + 2 次主体注水”，依此类推；
- 明确选择固定阶段冲煮法时隐藏重复的阶段数量选择器；
- 新增改良 4:6「33666」方案，240 g 总水量时固定为 30 / 30 / 60 / 60 / 60 g，前两段使用闷蒸温度；
- 冲煮优化器完成计算后再次锁定阶段结构，避免优化过程改变用户选定的注水方式；
- 轨迹图重构为 v17 相位—时间模型，显示温度带、流量带、累计注水、阶段背景、风味窗口及风险规避区间。

### 品鉴流程与显示

- 专业品鉴五项偏好雷达图统一为 1–9 分；红色多边形使用 50% 透明度；
- 跳过后续重复的质量评分步骤，避免同一评分重复录入；
- 从札记返回时继续停留在专业品鉴流程；
- 风味温区摘要统一使用 `H/W/C`，缺失温区用 `-`，不再显示“强度”文字或数值范围。

### 四象限快捷菜单

- 右下角四象限快捷菜单继续支持拖拽移动；
- 中央拖拽圆点由 26 px 扩大为 42 px，并增加外圈互动热区，提升手机触控和单手拖动成功率；
- 四个文字功能按钮仍保持独立点击，不会被拖拽手势误触。

## v0.9.6

### 豆袋 OCR、字段纠错与网页内摄像头

- “拍袋录入”支持正面主体、背面参数、侧面补充和日期标签，最多四张；
- 网页端使用 Tesseract.js 6.0.1，默认语言顺序为 `chi_sim + eng`，中文优先、英文辅助；
- OCR 前执行放大、灰度、对比度拉伸和 Otsu 二值化，并按稀疏文字/整块文字两种页面分割模式复核；
- 网页内 `getUserMedia()` 直接打开摄像头取景，支持后置镜头、前后切换、自动对焦提示和 `ImageCapture.takePhoto()` 高清拍摄；不支持时回退为视频帧截图；
- 识别证据改为“字段 / 当前值与候选 / 置信度 / 原始证据”四列；
- 候选器按国家、产区、庄园/处理站、豆种、处理法等字段分别匹配，并使用国家—产区—实体关系过滤；
- 支持全角横线、Unicode 横线、横线两侧空格和常见 OCR 形近字符；
- 初始克重、海拔、Agtron、日期、价格单独做数值候选，不再把 `15G82%` 等单位与置信度拼成一个值；
- Tesseract 对艺术字体和形近汉字仍有上限，候选值必须允许人工确认，不能将网页 OCR 结果视为无误数据。

识别架构详见 `docs/recognition-architecture.md`。

### 二维码与编码文本

- 摄像头二维码扫描使用 ZXing Browser 0.2.0，支持时使用 `BarcodeDetector`，兼容环境回退至 jsQR 1.4.0；
- 支持 BrewIon 二进制、HEX、JSON、编码表文本和 Lucky Bean 分享二维码；
- 结构化文本、正式编码和分享格式先解析，只有真正的二进制包才进入 CRC16；
- 正式编码可以从 OCR 文本直接识别，包括国家、产区、实体、豆种、处理法、风味与烘焙度代码；
- 富贵盒子新分享格式维持 `LB8R/LB8J` 外层兼容，在内部使用 `E` 标记 AES-GCM 加密载荷；旧 LB8 分享仍可读取。

### 冲煮方案完整性与变量轨迹

- 用户明确选择“一刀流、二段式、三段式、四六法、平底四六法、五段式”等方案后，修正引擎不得静默改成另一种冲煮法；
- 一刀流固定为“闷蒸 + 一刀流主萃”两段；其他方案同样执行阶段数量校验，错误时直接报错；
- 品鉴后的修正方案只调整温度、研磨、水量、风味目标等变量，保留用户指定的方案类型；
- 轨迹模型按实际阶段水量、流速、段间等待、粉量、粉水比、研磨、烘焙度/Agtron、处理法、豆种、Ca、Mg、HCO₃⁻、TDS、搅动和滤杯旁路逐时间步计算；
- 详细模型生成 81 个时间采样点，计算温度、流量、累计水量、相对萃取推进、花香、酸质、甜感、醇厚、苦涩和收敛风险；
- 修改温度、研磨、水质、冲煮法或风味目标后，轨迹曲线必须变化；
- 轨迹属于变量响应的相对预测模型，不是折光仪 TDS/EY 实测值，也不能替代实际杯测。

### 品鉴记录、历史展示与隐私

- 专业品鉴的标签、强度、雷达图、偏好评分和应用映射分结构化保存，不再把专业摘要写入札记；
- 札记仅保存用户自然语言，最大 300 字，并显示字符计数；
- 历史品鉴和历史冲煮记录以标签、雷达缩略图、评分和完整多行札记展示，不再只保留第一行；
- 内部风味编码只用于存储、同步和统计，界面只显示可读标签；
- 常用评价标签映射为短数值代码，记录写入前压缩；
- 品鉴记录在 IndexedDB 中使用 AES-GCM-256 加密，读取时透明解密；
- 冲煮记录不再重复保存札记明文；登录身份对象在设置表中加密，明文 `publicId`、邮箱、电话等不写入普通设置字段；
- 分享载荷删除明文用户 ID 和昵称，压缩后使用 AES-GCM 加密；任何拿到完整二维码或分享链接的人仍可读取分享内容，因此这不是账户级访问控制。

### 品鉴入口与极简身份页

- 完成冲煮并记录消耗后，只进入品鉴主页，不自动创建或启动品鉴流程；
- 小酌页两个“直接品鉴”入口同样只进入“专业品鉴 / 玩家互动品鉴 / 札记”选择页；
- 登录页只保留“登录 / 注册 / 本地使用 / 测试”四个入口，不显示 Logo、说明文案或其他装饰；
- 注册功能当前未开放；已经存在本地身份的设备直接进入应用，不重复询问。

### 三种品鉴模式

1. **专业品鉴**：专业杯测品鉴 / 雷达图 / 札记  
   使用标签化描述性评估、0–15 强度、双雷达图和五项 1–9 偏好评分。豆卡已有风味优先显示并标记“原”；已选标签可以拖动排序，排序靠前代表感知强度更高。评分位于流程末端，完成后直接进入札记。
2. **玩家互动品鉴**：风味互动 / 札记  
   保留逐项风味互动，完成后进入评分和札记。
3. **札记**：自然语言记录，评分  
   跳过风味互动，仅保留评分与自然语言札记。

专业品鉴参考 SCA Coffee Value Assessment 的描述性评估与偏好评估分离思路、CATA 标签和 9 点偏好量表。标签拖动排序、温区拆分、雷达图和应用映射建议分是富贵盒子的产品化扩展，不是 SCA 官方表单字段，也不构成 SCA 认证杯测结果。

## 数据与安全边界

- 数据默认保存在当前设备 IndexedDB；
- 本地 AES 密钥同样保存在当前浏览器的 IndexedDB 元数据表中，可防止普通导出或直接查看明文，但不能抵御同源恶意脚本、浏览器账户被接管或设备失陷；
- 加密分享的密钥包含在分享字符串中，目的是避免数据库、日志和二维码内容直接出现用户 ID 或自然语言明文，不构成只有特定账户可解密的权限系统；
- 真实邮箱/微信注册、跨设备同步、跨用户留言和服务端密钥托管仍需独立后端；网页不会伪装为已经完成这些能力。
