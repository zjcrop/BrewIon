## 1. 文档目的

本文档合并以下两类内容：

1. 富贵盒子现有全部产品修改需求；

## 2. 项目定位

富贵盒子是一款以本地优先为基础的咖啡豆管理、冲煮辅助和感官记录工具，覆盖以下完整流程：

```text
咖啡豆录入 → 储藏与赏味期管理 → 冲煮方案生成 → 制作辅助
→ 感官评价 → 历史复盘 → 分享
```

核心原则：

- Local-first：豆卡、库存、设备、偏好和历史记录优先保存在用户本地；
- Mobile-first：优先适配安卓和 iOS 旗舰手机；
- Offline-capable：网络中断时仍可完成基本豆卡管理和本地冲煮；
- Structured data：咖啡基础数据使用统一编码；
- User-controlled data：用户可导入、导出和清除个人数据；
- Private computation：私有冲煮算法不得向公开网页泄露。

## 3. 三仓库职责划分

### 3.1 `zjcrop/luckybean`：公开前端应用

职责：

- 藏、烹、鉴、器四个主页面；
- 豆卡、库存和历史记录管理；
- IndexedDB 本地持久化；
- 调用 BrewIon 公共数据及二维码模块；
- 调用私有冲煮计算 API；
- 本地回退冲煮方案；
- 分享内容展示；
- GitHub Pages 或其他静态站点部署。

禁止：

- 在前端写入 GitHub 私有仓库 Token；
- 将私有冲煮模型下载到浏览器；
- 将本地模拟注册描述为真实账号系统；
- 将本地留言描述为跨用户留言系统。

### 3.2 `zjcrop/BrewIon`：公开咖啡基础数据和二维码协议

职责：

- 国家、产区、庄园/农场/处理站、豆种、处理法、风味等编码表；
- 二维码编码和解码协议；
- CJK16、自定义扩展、CRC 校验；
- 图片二维码解析的公共适配层；
- 发布清单和版本信息；
- 可被 Lucky Bean 缓存和自动更新的公共数据。

BrewIon 不负责：

- Lucky Bean 的私有冲煮算法；
- 用户账号、评论或私有数据；
- 直接维护 Lucky Bean 的 UI。

### 3.3 `zjcrop/brew-profiles`：私有冲煮计算项目

职责：

- 私有冲煮算法；
- 品种、处理法、烘焙度、水质、器具和感官目标的计算模型；
- 模型版本管理；
- 输入输出协议；
- 回归测试；
- 服务端计算函数。

访问方式：

- Lucky Bean 只能通过受控 HTTPS API 调用；
- GitHub 凭据仅存在服务端环境变量；
- 浏览器不得直接读取私有仓库源码、JSON 配方或 WASM 模型；
- 每次计算结果必须返回引擎版本和方案版本。

### 3.4 架构关系

```text
BrewIon（公开）
  ├─ coffee-codebook.json
  ├─ qr-core.esm.js
  └─ manifest.json
            ↓ 公共、可缓存、可离线回退
Lucky Bean（公开前端）
  ├─ IndexedDB
  ├─ 豆卡和感官 UI
  ├─ BrewIon 客户端
  └─ Brew API 客户端
            ↓ HTTPS 请求
Private Brew API
            ↓ 服务端受控读取
brew-profiles（私有）
```

## 4. 术语和页面命名

### 4.1 命名层级

应用采用“单字导航 + 双字题注 + 专业正文”的三级命名体系。

| 导航单字 | 页面顶部题注 | 功能范围 | 图标 |
|---|---|---|---|
| **藏** | **豆藏** | 咖啡豆录入、储藏、养豆、赏味期、库存和老黄历 | 正方形 |
| **烹** | **手作** | 冲煮方法选择、方案计算、计时执行和制作记录 | 倒三角 |
| **鉴** | **品鉴** | 感官评价、评分、风味记录、纠错和历史比较 | 圆形 |
| **器** | **器设** | 器具、滤纸、磨豆机、调水、偏好、数据和系统设置 | 六边形 |

命名规则：

- 底部导航只显示单字“藏、烹、鉴、器”；
- 每个标签页最上方显示对应双字题注“豆藏、手作、品鉴、器设”；
- 页面正文、按钮和数据字段继续使用准确的专业术语；
- 产品文档中可使用“藏页、烹页、鉴页、器页”作为页面简称；
- 不把“冲煮方案”改成“烹方案”，也不把“感官评价”机械改成“鉴评价”；
- 无障碍标签必须使用完整功能名，例如 `aria-label="豆藏：咖啡豆管理"`；
- 页面路由、数据库键名和代码变量使用稳定英文标识，不直接使用中文题注作为内部主键。

建议内部路由：

```text
/beans      → 藏 / 豆藏
/brew       → 烹 / 手作
/sensory    → 鉴 / 品鉴
/settings   → 器 / 器设
```

### 4.2 视觉层级

页面顶部题注建议采用：

- 字数固定为两个汉字；
- 字号大于正文、小于品牌主标题；
- 字重 600–700；
- 适度增加字间距；
- 不使用仿古印章字体，以避免小屏识别困难；
- 可使用宋体或现代宋体作为展示字体，正文仍使用系统无衬线字体；
- 单字导航与双字题注必须保持一一对应，不允许出现旧称混用。

### 4.3 全局术语替换

| 原词 | 规范词 |
|---|---|
| 豆仓 | 盒子；导航用“藏”，页面题注用“豆藏” |
| 豆标 | 豆卡 |
| 储页 | 藏页 |
| 制页 / 手作页面 | 烹页；页面题注为“手作” |
| 品页 / 感官页面 | 鉴页；页面题注为“品鉴” |
| 仪页 / 设置页面 | 器页；页面题注为“器设” |
| 添加豆标 | +1 |
| 进入冲煮 | 整一杯 |
| 取消冷藏 | 解除冷藏 |
| 放进老黄历 | 放老黄历 |
| 最近感官记录 | 最近品鉴记录 |
| 更多旧记录 | 删除该固定文字 |

## 5. 优先级与发布门槛

### 5.1 优先级定义

- P0：阻止应用启动、导致数据损坏、造成凭据或算法泄露；
- P1：核心功能不可用、数据源不一致、明显安全问题；
- P2：交互、性能、可维护性和视觉问题；
- P3：增强功能和后续联网能力。

### 5.2 首次正式部署门槛

以下条件全部满足后，才允许发布至正式 GitHub Pages：

- 页面启动无未处理异常；
- 旧数据迁移可重复执行；
- BrewIon 数据缓存、校验和回退可用；
- 二维码图片和摄像头扫描可用；
- 相机关闭后释放 MediaStream；
- 烹页可生成本地回退方案；
- 私有冲煮 API 失败时不会阻断页面；
- 品鉴流程可完整保存；
- 导入文件经过 Schema 校验；
- 用户输入写入 HTML 前完成转义；
- 关键浏览器自动化测试通过；
- 版本号在代码、关于页面和发布清单中一致；
- 底部导航和页面题注严格对应“藏—豆藏、烹—手作、鉴—品鉴、器—器设”，不残留旧称。

## 6. 首页、登录与用户身份

### 6.1 品牌和入口

登录页必须显示：

- 标题：富贵盒子；
- 邮箱注册；
- 微信注册；
- 游客模式进入；
- 测试。

“测试”继续承担生成示例数据并进入应用的功能。

### 6.2 游客模式

游客模式必须支持：

- 豆卡录入；
- 储藏和库存；
- 制作方案；
- 品鉴记录；
- 本地备份和恢复。

游客模式限制：

- 不具有服务端用户身份；
- 不支持跨设备同步；
- 不支持需要服务端持久化的留言；
- 分享链接可匿名生成，但不能伪造为已注册用户。

### 6.3 真实注册的工程约束

邮箱、微信、QQ、手机号绑定均属于后端能力，不能只写入 `localStorage` 后称为注册成功。

正式账号系统至少需要：

- 服务端用户表；
- 唯一用户 ID；
- 邮箱验证或 OAuth；
- 会话 Token；
- 注销和解绑；
- 隐私政策；
- 接口限流；
- 账号数据删除。

在后端未部署前，相关按钮应标为“功能预留”或“本机身份”，不得使用“注册成功”等误导文案。

### 6.4 用户 ID

服务端用户 ID 应满足：

- 全局唯一；
- 不直接暴露邮箱或手机号；
- 分享时使用公开短 ID；
- 支持密钥轮换或撤销；
- 本地保存的只是公开 ID 和会话信息，不保存 OAuth 密钥。

### 8.4 搜索弹层

搜索面板必须包含：

- 豆名和录入信息关键词；
- 标签多选；
- 排序字段；
- 升序/降序；
- 确认；

排序字段至少包括：

- 推荐；
- 名称；
- 赏味期；
- 烘焙日期；
- 剩余克重；
- 复购评分；
- 价格；
- 最近品鉴得分。

确认后：

- 关闭弹层；
- 更新 `state.filter`；
- 重新渲染豆卡；
- 显示当前筛选条件；
- 无结果时显示明确空状态。

### 8.5 推荐弹层

推荐弹层位于推荐按钮正上方，竖直排列：

- 喜好：红色；
- 赏味期：绿色；
- 价格：金色；
- 余粮：白色；
- 点兵点将：橙色，尺寸更大。

每个圆点旁显示说明文字。

### 8.6 点兵点将

原需求中的“随机数必须大于 3 且小于 10”与“随机数小于等于 3 时等于 3”互相冲突。

本方案采用可验证规则：

```javascript
const n = Math.floor(Math.random() * 6) + 4;
```

结果固定为 4–9。

选择规则：

- 豆卡不足 9 个时，对当前可见豆卡数量取模；
- 不允许选中已归档或剩余量为 0 的豆卡；
- 先播放逐卡高亮动画；
- 最终豆卡使用蓝色高亮；
- 动画结束后滚动至目标豆卡。

## 9. +1 新豆录入流程

### 9.1 入口

点击 +1 后显示三个选项：

- 拍照识别；
- 二维码识别；
- 文字识别。

三个入口最终必须进入同一个豆卡表单，并允许人工修改。

### 9.2 拍照识别

流程：

1. 请求相机权限；
2. 拍摄豆袋、标签或二维码；
3. 尝试识别二维码；
4. 调用 BrewIon 协议解码；
5. 映射至表单；
6. 无二维码时保留图片并提示转文字录入。

不得只弹出 Toast 模拟功能。

### 9.3 二维码实时扫描

流程：

1. 打开后置摄像头；
2. 使用受控帧率扫描；
3. 识别二维码原始字节；
4. 校验 CRC；
5. 解码固定字段和自定义扩展；
6. 映射至 BrewIon 统一代码；
7. 关闭并释放摄像头；
8. 进入表单。

性能要求：

- 扫描帧率建议 5–10 fps；
- 不得每 250 ms 创建全分辨率新 Canvas；
- Canvas 和图像缓冲复用；
- Object URL 使用后必须 `URL.revokeObjectURL()`；
- 页面关闭、切换和异常时都必须停止 MediaStream。

### 9.4 文字识别

文字页包括：

- 大文本框；
- 语音录入按钮；
- 识别按钮；
- 清空按钮；
- 覆盖已有字段开关；
- 字段、证据、置信度和回填状态。

解析规则：

- 采用 BrewIon 编码表的中英文名和别名；
- 使用国家—产区—实体关系缩小候选；
- 对海拔、烘焙日期、色值、产季采用确定性正则；
- 低置信度字段不得静默覆盖；
- 浏览器语音服务是否联网必须明确提示。

### 9.5 表单回退

豆卡表单记录来源：

- manual；
- photo；
- qr；
- text。

返回按钮应返回对应上一步，并保留原图或原文字内容。

## 10. 豆卡表单

### 10.1 顶部

删除“遇到总表没有的国家……”等长说明。

保留简短状态信息：

- 数据库版本；
- 数据来源；
- 离线/在线状态。

### 10.2 字段等级

字段分为：

- 必填；
- 推荐；
- 可选。

必填使用“*必填”，不再使用“重点”。

推荐字段使用深紫色边缘：

- 是否冷藏；
- 购买价格；
- 烘焙商。

HTML 必须使用：

```html
<div class="bean-form-field is-recommended">
```

不得写成无效的 `is-recommended` 属性。

### 10.3 必填字段

至少包括：

- 豆卡名称；
- 国家；
- 豆种；
- 处理法；
- 烘焙度；
- 烘焙日期；
- 初始克重。

### 10.4 剩余克重

表单删除剩余克重输入框。

逻辑：

```text
首次保存：剩余克重 = 初始克重
后续变化：剩余克重 = 初始克重 - 所有有效库存扣减 + 所有有效库存修正
```

库存修改必须写入日志，不允许只覆盖当前数值。

### 10.5 风味标签

表单只显示：

- 已选择标签摘要；
- “编辑风味标签”按钮。

点击后进入全屏风味编辑器：

- 按 BrewIon 风味层级分类；
- 支持搜索；
- 支持多选；
- 支持清空；
- 确认后回到表单；
- 最多标签数需要配置；
- 不得继续维护独立 `FL-*` 风味代码。

## 11. 藏页豆卡列表与分组

### 11.1 分组触发

- 当前有效豆卡数量不超过 6：平铺；
- 超过 6：强制分组；
- 默认按国家分组。

### 11.2 分组方式

- 国家；
- 豆种；
- 烘焙度；
- 处理工法。

每组标题显示：

```text
分组名称（N只）
```

### 11.3 分组渲染

要求：

- 只保留一个正式 `renderBeans()`；
- 删除三次覆写和死代码；
- 分组逻辑拆成纯函数；
- 每组排序稳定；
- 当前筛选先执行，再分组；
- 推荐高亮不改变原始数组；
- 空组不渲染。

### 11.4 豆卡状态

豆卡至少显示：

- 名称；
- 国家；
- 豆种；
- 烘焙日期；
- 剩余克重；
- 赏味状态；
- 价格或克价；
- 冷藏状态。

状态颜色继续反映：

## 13. 分享功能

### 13.1 展示

分享使用 Modal 或全屏 Overlay，不离开主应用。

支持：

- 二维码分享；
- 链接分享；
- 复制完整链接；
- 保存二维码 PNG；
- 保存静态分享 HTML。

链接文本使用省略显示，但复制时复制完整 URL。

### 13.2 分享数据

分享内容至少包括：

- 豆卡公开信息；
- 冲煮方案；
- 品鉴结果；
- 分享时间；
- 应用版本；
- 方案引擎版本；
- 可选公开用户 ID。

不得默认包含：

- 邮箱；
- 手机号；
- 微信；
- QQ；
- 内部数据库 ID；
- 私有计算输入细节。

### 13.3 链接长度

不得无限制将完整历史、图片和评论编码进 URL Hash。

第一阶段：

- 仅分享压缩后的单次豆卡、方案和品鉴；
- 设置最大字节数；
- 超限时改为保存 HTML 文件。

第二阶段：

- 使用服务端短链接；
- 分享数据存储在后端；
- 支持撤销和过期。

### 13.4 留言

跨用户留言必须使用后端数据库。

未部署后端前：

- 可提供本机备注；
- 必须明确标注“仅保存在本机”；
- 不得描述为访问者共同留言。

## 16. BrewIon 数据同步

### 16.1 唯一主数据

Lucky Bean 不再长期维护独立大段 `OFFICIAL_CODES`。

统一以 BrewIon 为主数据：

- `countries`；
- `regions`；
- `entities`；
- `varieties`；
- `processes`；
- `flavors`；
- `relations`；
- `aliases`。

Lucky Bean 独有数据继续本地维护：

- 烘焙度；
- 滤杯；
- 滤纸；
- 调水；
- 注水手法；
- 制作形式。

### 16.2 发布文件

BrewIon 建议提供：

```text
dist/
├─ manifest.json
├─ coffee-codebook.json
├─ coffee-qr-core.esm.js
└─ checksums.json
```

### 16.3 更新策略

每次启动执行非阻塞检查：

1. 先加载本地已验证缓存；
2. 正常进入应用；
3. 后台请求远程 `manifest.json`；
4. 比较版本；
5. 下载新数据；
6. 校验 Schema 和 SHA-256；
7. 成功后原子替换缓存；
8. 失败则保留旧版本；
9. 下次启动使用新版本。

器页同时提供“检查编码表更新”按钮。

这兼顾“自动更新”和“手动控制”，不允许远程错误数据直接覆盖当前可用版本。

### 16.4 数据版本

每条豆卡保存：

- `codebookSchemaVersion`；
- `codebookDataVersion`；
- 原始 BrewIon 代码；
- 解析时显示名称不重复持久化，或仅作为快照。

## 25. 最终决策摘要

1. 品牌统一为“富贵盒子”；
2. 四页导航统一为“藏、烹、鉴、器”，页面顶部题注统一为“豆藏、手作、品鉴、器设”；
3. BrewIon 是公开豆信息与二维码唯一主数据源；
4. `brew-profiles` 是私有冲煮计算源；
5. 私有算法只能通过服务端 API 调用；
6. GitHub Pages 不能独立提供真实注册和跨用户留言；
7. 剩余克重由库存事件计算，不在新豆表单手填；
8. 风味标签统一采用 BrewIon 编码；
9. 启动时非阻塞检查更新，失败使用缓存；
10. 不再维护多套覆写函数和单文件补丁链；
11. 首次发布前优先完成 P0、P1 和数据迁移；
