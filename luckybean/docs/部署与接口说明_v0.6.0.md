# 富贵盒子 v0.6.0 部署与接口说明

## 1. Lucky Bean 前端

将压缩包内容覆盖到 `zjcrop/luckybean` 仓库根目录，保留以下结构：

```text
index.html
styles.css
manifest.webmanifest
sw.js
src/
public/
tests/
docs/
server/
.github/workflows/pages.yml
package.json
```

提交前执行：

```bash
npm test
npm run check
```

推送到 `main` 后，`Deploy Lucky Bean Pages` 工作流会：

1. 执行单元和静态检查；
2. 只复制 `index.html/styles.css/manifest/sw/src/public` 到 `_site`；
3. 部署 GitHub Pages；
4. 不把 `server`、`tests` 和内部文档作为网页资源发布。

在仓库 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**。

## 2. BrewIon 数据源

默认远程编码表：

```text
https://raw.githubusercontent.com/zjcrop/BrewIon/main/coffee-qr-codebook/coffee_qr_codebook_v6.json
```

应用启动顺序：

1. 读取 IndexedDB 中最近一次验证成功的 `active`；
2. 无缓存时读取 `public/fallback-codebook.json`；
3. 页面进入后后台检查远程文件；
4. 校验结构、编码唯一性和 SHA-256；
5. 同一事务写入 `candidate` 和 `active`；
6. 失败时继续使用旧版本。

待 BrewIon 发布 `dist/manifest.json` 和二维码 ESM 后，只需替换 `src/codebook.js` 的获取层，无需改变豆卡数据结构。

## 3. brew-profiles 私有接口

浏览器不得直接读取私有仓库。部署 `server/cloudflare-worker.js`，并配置：

- `GITHUB_REPOSITORY=zjcrop/brew-profiles`
- `GITHUB_REF=main`
- `PROFILE_PATH=profiles/default.json`
- `ALLOWED_ORIGINS=https://zjcrop.github.io`
- `GITHUB_TOKEN`：通过 Secret 注入，只读私有仓库
- 可选 `RATE_LIMIT_KV`

把部署后的完整 HTTPS 地址填写到：

```text
器 → 器设 → 私有冲煮 API
```

前端每次生成方案时先请求该 API；超时、HTTP 错误或 Schema 无效时使用本地回退引擎。

## 4. brew-profiles 最小文件

将 `server/profile.example.json` 复制至私有仓库：

```text
profiles/default.json
```

每次更新至少提升：

- `version`
- `engineVersion`（算法有行为变化时）

历史冲煮记录会保存响应版本，避免后续模型更新破坏复刻能力。

## 5. 缓存和发布

发布新前端版本时同步修改：

- `src/utils.js` 中 `APP_VERSION`
- `sw.js` 中 `CACHE_NAME`
- `package.json` 中 `version`
- `CHANGELOG.md`

否则旧 Service Worker 可能继续使用前一版本缓存。

## 6. 当前阻塞

当前 ChatGPT GitHub integration 对 `zjcrop/luckybean` 的创建分支和写文件操作返回 403。需要在 GitHub App 安装设置中为该仓库授予 **Contents: Read and write** 和 **Pull requests: Read and write**，或手工解压后提交。
