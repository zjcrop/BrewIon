# Coffee Foundation 日期兼容规则

日期识别属于跨项目基础能力。OCR 只负责保留原文和位置证据；`parseCoffeeDate` 负责把日期候选规范化为 `coffee-date-decision/1.0`，消费者只有在 `status=confirmed` 或用户明确确认后才能写入 `roastDate`。

## 支持的输入

| 类别 | 示例 | 决策 |
|---|---|---|
| 中文/日文年月日 | `2026年7月15日`、`二〇二六年七月十五日` | 明确日期可确认 |
| 中文大写数字 | `贰零贰陆年柒月拾伍日`、`柒月拾伍日` | 年月日完整可确认；缺年待确认 |
| 中文变体 | `两`/`兩`、`廿`/`念`、`卅`、简繁体财务数字 | 规范化后解析 |
| 英文月份 | `July 15, 2026`、`15th July 2026`、`15 JUL 2026` | 月份名消除顺序歧义 |
| 数字日期 | `2026-07-15`、`2026/7/15`、`20260715` | 年优先格式可确认 |
| 美英数字顺序 | `07/15/2026`、`15/07/2026` | 数值或 `en-US`/`en-GB` 可消歧；`03/04/2026` 无地区信息时冲突 |
| 日本和历 | `令和8年7月15日`、`R8.7.15` | 转换并校验元号真实起止日 |
| 民国纪年 | `民國115年7月15日`、`ROC 115/7/15` | 转换为公历并保留原历法证据 |
| 韩国日期 | `2026년 7월 15일`、`이천이십육년 칠월 십오일` | 转为公历日期 |
| 缺少年份 | `七月十五日`、`July 15`、`7월 15일` | 保留月日；可用可信参考日提出最近过往年份候选，但仍待确认 |
| 两位年份 | `15 JUL 26`、`07/15/26` | 不猜世纪，待确认 |
| 非公历/相对日期 | `农历七月十五`、`yesterday` | 不静默换算 |

## 安全规则

1. 最终规范日期仍为 `YYYY-MM-DD`，不会改变 `coffee-canonical-record/1.0`。
2. 原始文字、规范化文字、命中的标签、解析模式、候选与证据引用必须同时保留。
3. 缺年、两位年份、数字顺序冲突、无效日期和非公历日期不得自动写入。
4. `best before`、`赏味期限`、`生产日期`等标签不得冒充 `roastDate`；字段不一致时必须复核。
5. 日本元号不仅换算年份，还必须校验改元日，避免把 `平成31年5月1日`等不存在的和历日期当作有效日期。
6. 基座不依赖云服务或第三方日期库，离线行为必须确定且可回归。

## 依据

- [Unicode CLDR/LDML Date Formats](https://unicode.org/reports/tr35/tr35-dates.html)：按语言地区区分日期字段、月份名、数字顺序和历法；年月日与月日都是有效的日期字段组合。
- [Unicode CLDR Numbering Systems](https://unicode.org/reports/tr35/tr35-numbers.html)：语言和历法可使用不同数字系统。
- [出版物上数字用法的规定](https://www.qinghai.gov.cn/sdfz/article/content/f26f22af86f8bd4a589e5f75840e78c3.html)：中文数字存在普通和大写（壹贰叁肆伍陆柒捌玖拾等）形式。大写日期作为 OCR 容错输入兼容，不表示建议使用该日期书写规范。
- [日本内阁府元号资料](https://www.cao.go.jp/others/soumu/gengou/index.html)与[西历—和历对照说明](https://jsite.mhlw.go.jp/hokkaido-hellowork/urakawa-career-guide.html)：和历转换必须按真实改元日校验，不能只做年份加减。
