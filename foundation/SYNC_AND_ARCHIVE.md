# 同步与归档基座规则

## 同步修订

- `coffee-sync-revision/1.0` 是跨项目共享的不可变修订信封，不替代 LuckyBean 或 AromaSense 的业务表结构。内容哈希统一使用 `sha256-canonical-json-v1`（对象键排序、数组顺序保留、UTF-8 JSON）。
- 同一个 `revisionId` 与同一个 `contentHash` 重复上传时必须幂等返回；同一个 `revisionId` 出现不同哈希时必须返回冲突，禁止静默覆盖。
- 活跃编辑期间以本地事务存储为事实来源。云端只接收已经落盘的修订，不得阻塞当前记录。
- 删除使用显式 `tombstone` 修订；回收站期限、展示方式与最终清理由各应用决定。
- `payloadContract` 必须写明业务负载的合同版本，未知主版本不得自动迁移或覆盖本地数据。

## 归档

- `coffee-archive/1.0` 是跨应用可检查的外层清单。每条业务记录继续保留自身合同，不强迫不同应用共享 UI 或完整数据库。
- 每条记录包含 SHA-256；导入顺序固定为“读取候选 → 校验合同主版本/字节数/哈希 → 预览 → 用户确认 → 单事务写入”。
- 校验失败或出现未知未来主版本时，保留当前数据和最后一个已验证基座，不允许部分写入。
- 历史 BrewIon 代码、二维码行号和消费者自有记录 ID 均不得在迁移时重排或复用。
